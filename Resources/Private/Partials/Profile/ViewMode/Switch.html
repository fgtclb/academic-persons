The visitor switch between the view modes: one link per mode, the active one marked as current. It renders nothing while the content element does not offer it or fewer than two modes are allowed - the action then assigns no "viewModes". A link changes the view mode and nothing else. In the list elements the mode is part of the demand, and a link keeps the other choices of the visitor, activeListArguments; the link to the default mode carries no mode at all, so the list keeps its plain URL - the page itself when the visitor chose nothing else. The selected profiles and contracts elements have no demand, and their mode is a plugin argument of its own. The label of a mode is "list.viewMode." of EXT:academic_persons, the mode itself for a project mode without a label. Arguments: - viewModes: the modes the switch offers - viewMode: the active mode - defaultViewMode: the default mode of the content element - activeListArguments: the visitor's choices of a list element - inDemand: set by the list elements, whose mode is part of the demand
    A link that carries nothing is the page itself: an action link would carry the controller, and with it a query string and a cHash.
